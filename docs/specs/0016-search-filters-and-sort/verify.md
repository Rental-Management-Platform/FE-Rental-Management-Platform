## Found by the M4 checks

- `/dev/ui` raised "Route "/dev/ui": Next.js encountered the unstable … blocking-prerender-current-time-client". With Cache Components Next prerenders Client Components too, and TanStack Query reads the current time when it makes an active query; the samples that use the real ward box (`useWards`) must sit behind a `<Suspense>`. Fixed in `search-filters.tsx`. The real page does not raise it: `npm run build` passes and its console is clean on the dev server and on the production build.
- On the phone widths `focusDraftField` picked the first visible copy of a box in the whole document, and `/dev/ui` has several copies, so a wrong price in the sheet sent focus behind the modal. It now prefers a copy inside an open dialog. The real page has one visible copy, so nothing changed there.
- `/dev/ui` scrolled sideways at 320 px because the address line (`/?wardCode=…&minPrice=…&maxPrice=…`) cannot wrap; it now breaks anywhere.
- The fallback's grey ward block sat 28 px above the price blocks (the live ward box has a label row above it, the block had none). It is now level with them. The card height was already equal.
- Seen and left alone: from `lg` the ward button is 192 px wide (the `12rem` column of M2), so "Phường Bến Thành" shows as "Phường Bến Th…"; the chip below has the full name. A wider column would fix it.
