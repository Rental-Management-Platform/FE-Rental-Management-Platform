# Verify: API client & session layer · spec 0002 · updated 2026-10-23

_Steps derived from spec 0002 acceptance criteria. `/check verify` runs these; `/test` locks the durable ones. M1 steps are below; each later milestone appends its own._

## UI / manual

- [ ] Backend running, `npm run dev`, open `/dev/session`, press "Call GET /plans" → the page shows `total: 3` (seeded plans) → AC-1
- [ ] Stop the backend, press "Call GET /plans" again → the alert shows `NETWORK_ERROR (status 0)` with "Không kết nối được tới máy chủ..." → AC-10
- [ ] Network tab on the "Call GET /plans" request → the URL is `NEXT_PUBLIC_API_URL` plus `/plans`, with no `Authorization` header and no cookies sent (value sourcing: Full URL, Credentials) → AC-1, AC-2

**M2: login thread** (a reload shows `loading` until M3 adds the restore)

- [ ] As a guest, press "Call GET /auth/me" → the alert shows `TOKEN_MISSING (status 401)`, and the Network tab shows no request to `/auth/me` → AC-1
- [ ] Register a tenant (email, password, leave the rest) → the session panel reads `user: <email> · tenant · N permissions` (N comes from `/auth/me`, not from the account type), and the two forms disappear (value sourcing: Who is logged in, Permission check) → AC-3
- [ ] Right after, in the browser console: `localStorage`, `sessionStorage` hold no token, `document.cookie` is exactly `has_session=1`, and the address bar has no token → AC-3
- [ ] Application tab, Cookies: `has_session` has Path `/`, SameSite `Lax`, not HttpOnly, about 30 days (value sourcing: Hint cookie); `rt` is HttpOnly and was set by the API → AC-3
- [ ] Press "Call GET /auth/me" as the user → the output shows the email and permission count; the request URL is `NEXT_PUBLIC_API_URL` plus `/auth/me`, with `Authorization: Bearer ...` (value sourcing: Full URL, Authorization header) → AC-1
- [ ] Vary the account: sign in with a seeded landlord from `api-for-frontend.md` section 2 → the panel shows `landlord` and a different permission count than the tenant (the list comes from `/auth/me`, never inferred from `accountType`) → AC-3
- [ ] Sign in with a wrong password → the form shows `INVALID_CREDENTIALS (status 401)`, the state stays `loading` (no `endedReason`), and no `has_session` cookie is written → AC-3
- [ ] Sign in with email `abc` → the form shows `VALIDATION_FAILED (status 400)` as a form level message (the per field mapping arrives in M4) → AC-10
- [ ] Submit both forms empty → "Required" under each input and no request in the Network tab → AC-3
- [ ] Reload the page after signing in → the state is `loading`, `has_session=1` is still set, and no `POST /auth/refresh` is sent (restore arrives in M3) → AC-4 (expected gap until M3)

**M3: stay logged in** (backend with `ACCESS_TTL_SECONDS=60`; the debug panel on `/dev/session` shows the seconds left)

- [ ] As a guest with no `has_session` cookie, open `/dev/session` → the state is `guest (endedReason: none)`, the forms show, and the Network tab has no request to `/auth/refresh` (value sourcing: Restore on page load, whether to try) → AC-4
- [ ] Sign in, then hard reload → the panel goes `loading` then `user`, no login form shows in between, and the Network tab has exactly one `POST /auth/refresh` and one `GET /auth/me`, even in `next dev` where React StrictMode runs effects twice. This replaces the M2 reload step above → AC-4, AC-5
- [ ] The debug panel counts the token down from about 60 s (value sourcing: `expiresAt` comes from `expiresIn`, never a fixed 900) → AC-5
- [ ] With under 30 s left, press "Call GET /auth/me five times" → "5 of 5 succeeded", one `POST /auth/refresh` before the five `GET /auth/me`, and "refreshes sent" goes up by one (value sourcing: Early refresh margin, 30 s) → AC-5
- [ ] With under 30 s left, press "Call GET /listings" → the Network tab shows a refresh first, then `GET /listings` with the token, and the panel reads `first isFavorite: false`, not null → AC-7
- [ ] Vary the input: with under 30 s left, block `/auth/refresh` in DevTools and press "Call GET /listings" → the read still goes out with the old token and the session stays `user` (an optional read never fails because of a refresh) → AC-7
- [ ] Tick "Early refresh margin 0", wait until the panel says "expired", press "Call GET /auth/me" → the Network tab shows `GET /auth/me` 401, then `POST /auth/refresh`, then `GET /auth/me` 200, and "refreshes sent" goes up by one → AC-6
- [ ] Stop the backend (or block `/auth/refresh`) and reload while signed in → the state is `guest (endedReason: unavailable)`, `has_session=1` is still set, the "Check session again" button shows, and the console has a warning, not an error. Start the backend (or unblock) and press the button → `user` → AC-4
- [ ] In the Application tab delete the `rt` cookie but keep `has_session`, then reload → the state is `guest (endedReason: none)`, `has_session` is gone, and no error shows (a stale hint ends quietly) → AC-4

**M4: errors people can see** (as a guest, backend running; the 429 steps leave a 15 minute block on `lab-limit@example.com`, restart the backend to clear it)

- [ ] Sign in with email `abc` and any password → "Phải là địa chỉ email hợp lệ." shows under the Email input (marked `aria-invalid`), nothing under Password, and no form level message (value sourcing: Field errors, Error text). This replaces the M2 `abc` step above → AC-8
- [ ] Register with email `khoa.tran@demo.example.com` (a seeded account) and password `123123123` → the `EMAIL_TAKEN` message shows under the Email input, the forms stay, `document.cookie` is empty (value sourcing: Field errors, the fixed code map) → AC-8
- [ ] Register a landlord with a phone number that already belongs to another landlord → the `PHONE_TAKEN` message shows under the Phone input → AC-8 (needs a phone you know is taken)
- [ ] Press "Send 12 wrong logins" → "10 answered 401, then it stopped", the Vietnamese "Bạn thao tác quá nhanh..." message, "Hãy thử lại sau khoảng 15 phút.", and the button is disabled. "khoảng" is there because the browser cannot read `Retry-After` across origins (value sourcing: Wait after 429, Whether the wait is exact, Wait text) → AC-9
- [ ] Wait about a minute → the text reads "khoảng 14 phút" with no click (the countdown runs on its own) → AC-9
- [ ] While the block lasts, submit the Sign in form with `lab-limit@example.com` → the form shows the same message and wait, and its Sign in button is disabled; nothing is retried by itself (Network tab shows one `POST /auth/login`) → AC-9
- [ ] Vary the input: put the API behind the same origin (proxy mode) or add `exposedHeaders: ['Retry-After']` on the backend, repeat the twelve wrong logins → the wait reads "15 phút" with no "khoảng" and the seconds match the header → AC-9 (not run, needs backend or proxy change)
- [ ] In DevTools block the request URL `*/plans`, press "Call GET /plans" → the output shows "Calling… (retry 1)" about a second later, then `NETWORK_ERROR (status 0)` and "tried 2 times" → AC-10
- [ ] As a guest press "Call GET /auth/me" → `TOKEN_MISSING (status 401)` and "tried 1 time" (a 4xx is never retried) → AC-10

**M5: ending a session cleanly** (backend running; use seeded accounts with the demo password, so you do not hit the register limit; each sign in counts toward 10 per email and 30 per IP in 15 minutes)

- [ ] Sign in, press "Call GET /plans", "Call GET /auth/me" and "Call GET /listings" → the debug panel reads `cached queries with data: 3` → AC-12
- [ ] Press "Reload profile" → one `GET /auth/me` with the token, the panel stays `user`, and the line "Reload profile: done." shows → AC-11
- [ ] Press "Sign out" → `guest (endedReason: none)`, `has_session` is gone from `document.cookie`, the cache count reads 0, the three call results are back to "Not called yet.", the Network tab shows exactly one `POST /auth/logout` answered 204, and the `rt` cookie is gone (value sourcing: Reason a session ended, Hint cookie) → AC-11, AC-12
- [ ] After that, press "Call GET /auth/me" → `TOKEN_MISSING (status 401)` and no request in the Network tab (the local error of a guest never ends anything) → AC-11
- [ ] Vary the account: sign in as `huy.hoang@demo.example.com`, press "Call GET /auth/me", sign out, sign in as `khoa.tran@demo.example.com` → no `huy.hoang` text anywhere on the page, and the next "Call GET /auth/me" shows `khoa.tran` → AC-12
- [ ] Press "Sign out of all devices" → exactly one `POST /auth/logout-all` answered 204 with `Authorization`, and no second `POST /auth/logout`; the state is `guest (endedReason: none)`, the hint is gone, the cache count is 0 → AC-11
- [ ] Two browsers on one account: sign in on both, press "Sign out of all devices" in the first, then in the second wait until the panel shows under 30 s and press "Call GET /auth/me" → the second ends as `guest (endedReason: revoked)` and its cache count is 0 (the refresh answers `SESSION_REVOKED`) → AC-11
- [ ] Stop the backend, signed in, press "Sign out of all devices" → a red alert with `NETWORK_ERROR (status 0)` and the state stays `user` with the hint kept (the other devices are still signed in). Press "Sign out" instead → `guest (endedReason: none)` at once and a console warning, not an error → AC-11
- [ ] Signed in, delete the `rt` cookie in the Application tab, wait until the panel shows under 30 s, press "Call GET /auth/me" → the state becomes `guest (endedReason: revoked)`, `has_session` is gone, the cache count is 0, and the Network tab shows only `POST /auth/refresh` 401 (no `GET /auth/me` with a dead session) → AC-11, AC-12
- [ ] Sign in with `lan.bui@demo.example.com` (locked) → the form shows 403 `ACCOUNT_LOCKED`, and the state stays `guest (endedReason: none)`, not `locked` (a failed login sets no reason) → AC-11
- [ ] Signed in, press "Sign out" and sign in again straight away → the new session keeps its `rt` cookie and survives a reload (the login waits for the logout request) → AC-12
- [ ] Not run, needs an admin: lock a logged in account from the admin API, then press "Call GET /auth/me" or wait for the next refresh → `guest (endedReason: locked)` → AC-11
